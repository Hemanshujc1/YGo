# @ygo/mobile

Code both mobile apps use: the Customer and Shopkeeper apps, never the web apps or the server (ADR-0009).

- `AppShell`: wraps each app's root layout. It sets the system bars, runs the version check at launch and whenever the app comes back from the background, and shows `UpdateRequired` in place of the app once any call is refused.
- `showUpdateRequired`: each app passes it to `createApiClient` as `onUpdateRequired`, so a 426 `UPDATE_REQUIRED` from any call shows the update screen. It stays until the app restarts.
- `SessionGate`, `SessionGateWords`: each root layout wraps its `<Slot />` in it, inside `AppShell`. At launch it calls `session.check()`, then shows a blank screen in the theme colour while checking, `SignIn` while signed out, `Profile` until the name and phone are saved, "Can't reach YGo" with Try again when no answer came, and the app once signed in. After a sign-out that could not clear the phone's storage, C01 says so under the email until the person types. Each app passes its `session`, `api`, support email and words.
- `sessionStore`: each app passes it to `createApiClient` as `session`. The refresh token lives in `expo-secure-store`, on this phone only: the Keychain never syncs it, and each app's `app.json` lists the `expo-secure-store` plugin, which leaves it out of Android backups. Never in MMKV. A sign-out whose clear fails leaves a marker in MMKV, and while it is set the token is never handed out. A fresh install ignores a token an earlier install left in the Keychain, and a token that can't be read counts as none. A marker that can't be read counts as set. The client queues every store call in order, so a sign-in and a sign-out never overlap.
- `showSignedOut`, `createSession`, `useSession`: each app passes `showSignedOut` as `onSignedOut` and makes one `session = createSession(api)`. A new `createSession` takes the signal from the last, so Fast Refresh leaves no stale listener. `useSession(session)` answers checking, signed out, profile needed, signed in, or unreachable, which picks the screen.
- `SignIn`, `SignInWords`: C01 Sign in, then C14 Enter email code once a code is sent; the root layout shows it while signed out, with no sign-in routes. Each app passes `words` (its `strings.signIn` and `strings.errors`), the support email, its `api`, and `session.signedIn` as `onSignedIn`. The email is checked with `Email` and the code with `LoginOtp`, both from `@ygo/contracts`; the hidden code field only drops what is not a digit. "Send a new code" counts down 30 seconds from the time of the last send, so leaving the app never restarts it, and each email keeps its own wait: an email sent again inside it goes straight to C14, so A, then B, then A goes back to A's code. The sends are kept outside the screen until a sign-in, so a remount keeps each countdown and any shut boxes. Android Back on C14 goes to C01, except while a code is checked or sent. An optional `notice` shows under the email until the first keystroke. The support email can be pressed and held to copy, for a phone with no email app.
- `Profile`, `ProfileWords`: C02 Your name and phone number, shown after the first sign-in until both are saved. Each app passes `words` (its `strings.profile` and `strings.errors`), the support email, its `api`, `session.signedIn` as `onSaved` and `session.signOut` as `onSignOut`; both boxes start empty, since the server saves the name and phone together. The name is checked with `PersonName` and the phone with `Phone`, after a fixed +91; a pasted "+91 98765 43210" or "098765 43210" still works. Each refused field gets its own message and the first one to retype is focused; a phone in use points to the support email and is left unfocused, so the keyboard never covers it. Continue shows "Saving…" and Sign out a spinner, and both lock the screen until they settle.
- `findPlace`, `Locator`, `Found`: a "use my location" button's logic. Each screen passes a `Locator` built from its own `expo-location` calls, so the package needs no location module. `findPlace` asks for location while the app is in use, checks location is on for the phone, waits up to 15 seconds for a position, and keeps one only inside India. A found position carries its accuracy in metres, or null when the phone gave none or one that is not a positive number. Used by C15 (Customer).
- `Text`: React Native's `Text` set in Inter.
- `Button`, `SupportEmail`, `FieldMessage`, `edgeClass`: the parts C01, C14 and C02 are built from, for the apps' own screens. `Button` is the primary button (52 high) or the text button (48 high), with a spinner while busy. `SupportEmail` is the address as a link that opens a new email, and can be pressed and held to copy. `FieldMessage` is the red line under a refused field, read out when it appears. `edgeClass` gives a text box's edge: red when refused, else blue while focused.
- `applySavedTheme`: applies the theme choice saved in MMKV. Each root layout calls `applySavedTheme()` once, after importing its stylesheet, so a saved Light or Dark never flashes the system theme. Importing the package has no side effects.
- `ThemePicker`, `ThemePickerWords`: "Theme" over System / Light / Dark, for an app's settings screen. Each app passes `words` (its `strings.theme`: the label and the three names). A tap changes the whole app at once and saves the choice on this phone.

The package holds no words and reads no settings: each app passes its strings and store links as props. A component moves in only when both apps use it, and nothing only one app uses belongs here.

Each app's `tailwind.config.js` lists `../../packages/mobile/src/**/*.tsx` in `content`, or the classes here never get generated. Every peer dependency is pinned to the exact version both apps pin; bump them together.
